## 核心组件

### 1. 事件模型 (FlowEvent)
- 基于 Pydantic 的数据模型
- 包含 event_type / source / payload / metadata / context
- 支持 Builder 模式创建
- 支持序列化/反序列化

### 2. 消息总线 (MessageBus)
- 抽象基类定义发布-订阅接口
- MemoryMessageBus 提供进程内实现
- 支持通配符模式匹配（如 `test.*`）
- 支持队列分组和背压处理

### 3. 引擎系统 (FlowEngine)
- 抽象基类定义生命周期（start/stop/process）
- 支持事件订阅匹配
- 支持并发控制和重试机制
- 内置心跳和统计信息

### 4. 扩展系统 (Extension)
- Extension 基类用于第三方集成
- ExtensionProtocol 定义通信协议
- ExtensionRegistry 管理扩展注册

## 事件流 (以 DRC 修复为例)

```
时间 →  违例事件 ──→ 消息总线 ──→ DRC引擎
                                │
                                ├──→ 分析违例类型
                                ├──→ 选择修复策略
                                ├──→ 发布TOOL_STARTED ──→ EDA引擎
                                │                          │
                                │                          ├──→ 执行工具
                                │                          └──→ 发布TOOL_COMPLETED
                                │
                                └──→ 发布KNOWLEDGE_CAPTURE ──→ 知识引擎
                                                             │
                                                             ├──→ 提取知识
                                                             ├──→ 富化
                                                             └──→ 存储
```

## 工作流编排

FlowOrchestrator 支持定义多步工作流模板：

| 步骤 | ID | 说明 | 超时 |
|------|-----|------|------|
| 1 | violation_analysis | 违例分析（类型/严重程度） | 60s |
| 2 | repair_strategy | 修复策略选择 | 30s |
| 3 | tool_execution | EDA工具执行 | 300s |
| 4 | result_verification | 结果验证 | 60s |
| 5 | knowledge_capture | 知识入库 | 30s |

支持特性：
- 步骤依赖管理（前序步骤完成后才能执行）
- 超时控制（每个步骤独立配置）
- 错误重试（可配置重试次数）
- 工作流状态追踪

## 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| 运行时 | Python 3.10+ | 异步 (asyncio) |
| 数据模型 | Pydantic v2 | 事件模型定义 |
| API服务 | FastAPI + Uvicorn | REST API |
| 消息总线 | Redis (规划) | 跨进程事件分发 |
| 知识存储 | PostgreSQL / Qdrant / Neo4j | 混合存储 |
| 部署 | Docker + Kubernetes | 容器化 |
| 监控 | Prometheus + Grafana | 可观测性 |
